# AI Agent Definitions

## Agent Registry

---

## 1. MyServer System Operator (Primary Agent)

**Role:** Core orchestration agent running inside the local LLM daemon.

**Responsibilities:**
- Execute system commands via `exec_shell` protocol
- Analyze workspace code and project structure
- Coordinate with Workspace Code Assistant for code tasks
- Route security-sensitive commands to Security Guardrail Inspector
- Manage model loading and context window state

**Execution Protocol:**
```
Output Format:
1. Reasoning block (```thinking...```)
2. Action blocks (```exec_shell ... ``` or ```file_write ... ```)
3. Final response (concise technical summary)

Example:
The following reasoning and actions are generated by the MyServer System Operator.

[LOGGING] Loading workspace context...
[INFO] 142 files indexed from /home/user/project

To optimize the build configuration, I recommend updating the Makefile:
```file_write
path: /home/user/project/Makefile
content: |
  CC=clang
  CFLAGS=-O2 -march=native
  ...
```

Apply changes? [RUN COMMAND]
```

**Connection Targets:**
- WebSocket: 127.0.0.1:4096 (Daemon)
- Ollama API: 127.0.0.1:11434 (Local LLM)

---

## 2. Workspace Code Assistant (Specialized Agent)

**Role:** Code analysis and generation agent bound to selected workspace.

**Responsibilities:**
- Read and parse source files from workspace indexer
- Generate code snippets, refactoring suggestions
- Provide inline documentation and comments
- Suggest dependency updates and security patches

**Capabilities:**
```
Language Support:
- Go (gopls LSP integration)
- Python (pyright)
- Rust (rust-analyzer)
- C/C++ (clangd)
- JavaScript/TypeScript (tsserver)
- JSON/YAML/TOML (schema validation)
```

**Prompt Template:**
```
You are the Workspace Code Assistant for MyServer v1.14.33.
Analyze code in the workspace directory and provide precise, technical responses.
When code modifications are needed, use ```file_write``` blocks with full file paths.
Reference existing code patterns in the workspace when possible.
```

## 3. Security Guardrail Inspector (Defense Agent)

**Role:** Command validation and threat detection agent.

**Responsibilities:**
- Run incoming commands through regex blacklist
- Classify execution risk level (0, 1, 2)
- Block forbidden patterns before execution
- Generate audit trail entries

**Validation Flow:**
```
Incoming Command
    │
    ▼
Regex Match Against Blacklist
    │
    ├── [MATCH] → DENY → "SECURITY ALERT" logged
    │
    └── [NO MATCH] → Classify Level
                    │
                    ├── Level 0 → Auto-execute
                    │
                    └── Level 1/2 → Queue for GUI confirmation
```

**Blocked Patterns:**
```regex
# Root/system destructive
rm -rf /
rm -rf /*
del /f /s /q C:\*
rd /s /q c:\

# Disk formatting
mkfs.*
format c:
dd if=/dev/zero of=/dev/sd*

# System shutdown/reboot
shutdown -h now
init 0
reboot -f

# Privilege escalation
chmod -R 777 /
chown -R root /

# Registry/kernel manipulation
reg delete HKLM\System
sysctl -w kernel.*
```

**Alert Message (Standard Output):**
```
SECURITY ALERT: Identified potentially destructive command.
Execution aborted by Local Guardrail Engine.
```

## Agent Communication Matrix

| From Agent | To Agent | Channel | Purpose |
|------------|----------|---------|---------|
| System Operator | Any | Master Prompt | Dispatch work |
| Workspace Code Assistant | System Operator | exec_shell | Request command execution |
| System Operator | Security Inspector | Internal Validation | Pre-execution check |
| Security Inspector | System Operator | JSON Response | Approval/denial |
| Any | GUI | WebSocket Events | User interaction |
